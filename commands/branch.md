$ARGUMENTS

Tier: reversible/local (`git checkout -b` off an up-to-date remote ref) — no approval gate, but confirm the exact branch name before creating it. `$ARGUMENTS` is a ClickUp ticket reference (a URL or a bare custom ID like `GHLEN-22140`); extract the ID — the last `/t/` path segment, or the second segment if the URL has both a team ID and a custom ID after `/t/` — and delegate the lookup to `research-quick` (one narrow record fetch): read-only `clickup_get_task` by that ID, returning the title, description, and any type/tag/list hints. This workspace's custom task IDs use exactly two prefixes: `GHLEN-` and `GHLPRD-` (e.g. `GHLEN-22374`, `GHLPRD-1042`) — a bare custom ID matching `^(GHLEN|GHLPRD)-[A-Za-z0-9]+$` is valid on its own; don't invent or apply any other custom-ID format check (in particular, ClickUp's generic default `CU-` prefix does not apply here and must never be used to reject an otherwise-valid `GHLEN-`/`GHLPRD-` ID) — pass it straight to `clickup_get_task` and let that call itself be the source of truth on whether the ticket exists. Delegate repo evidence to `scout-quick` (three independent single-fact checks): confirm we're inside a git repo, run `git status --porcelain` to flag a dirty tree, and get the default branch via `git rev-parse --abbrev-ref origin/HEAD` (strip the `origin/` prefix) — scout's git allowlist covers `rev-parse` but not `symbolic-ref`/`remote show`, so this is the only way to get it from a read-only agent.

From research-quick's output, classify the prefix yourself: an explicit ClickUp type/tag or containing list name (e.g. a list literally called "Bugs") wins; otherwise keyword-match the title/description — fix/broken/regression/error → `bug`, refactor/cleanup/upgrade/migrate/docs → `chore`, else default `feat`. Compress the ticket's use case into a 3-6 word slug (lowercase, hyphens, no stopwords) — don't just slugify the raw title verbatim, actually summarize it. Assemble `<ticket-id>-<prefix>-<slug>` using the ticket's custom ID verbatim (exact case, exact prefix — `GHLEN-22140`, not `ghlen-22140` or a reformatted variant) as `<ticket-id>` (e.g. `GHLEN-22140-feat-add-sso-login`), surface it with the base branch and a one-line ticket summary, and get confirmation before creating anything — never invent or auto-create a name, and flag any dirty working tree `scout-quick` reported instead of proceeding silently. The assembled name must satisfy AGENTS.md § Git branch naming: letters, numbers, and hyphens only — no `/`, `_`, spaces, or nested prefixes; verify this before surfacing it for confirmation. If either `scout-quick` or `research-quick` reports the lookup wasn't as narrow as expected, re-route that one to the full agent rather than pushing it through anyway.

Once confirmed, delegate to `builder` to run `git fetch origin <default-branch>` then `git checkout -b <name> origin/<default-branch>` directly; `git fetch`/`git checkout -b` are plain `allow`, so this runs to completion with no manual hand-off. Do not use inline shell substitutions to construct the branch name — the literal string comes from your own assembled name, not a subshell. If a local branch with that name already exists, stop and ask whether to check it out instead of overwriting it.
